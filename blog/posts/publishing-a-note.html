This entry is written in raw HTML rather than Markdown, which is the escape hatch for notes that need markup Markdown cannot express — a custom diagram, an inline SVG, a table with merged cells. Everything else on this site treats the two identically.

It is also flagged "draft": true, so it stays out of the public index and is only reachable with ?drafts=1. That is the workflow for anything half-written.

Adding a note

  1. Drop a file in blog/posts/ — my-note.md or my-note.html.
  2. Register it in blog/posts.json, or run node tools/build-index.mjs to regenerate the manifest from the files themselves.
  3. Commit. GitHub Pages serves it; there is no build step.

Markdown front matter

Markdown entries carry their own metadata, which wins over the manifest when both define the same field:

---
title: Where a slow page actually comes from
date: 2026-08-14
tags: [full-stack, performance]
summary: One sentence that shows up on the index.
---

Manifest fields

FieldRequiredNotes
slugyesURL key: post.html?p=<slug>
titleyesShown on the index and as the page title
dateyesYYYY-MM-DD; sorts the archive
summarynoOne line under the title on the index
tagsnoDrives the filter chips
formatnomd (default) or html
filenoDefaults to posts/<slug>.<format>
draftnotrue hides it from the index

What the reader adds for free

  • Headings become anchored and feed the table of contents, which tracks scroll position.
  • Code blocks get a language label, a copy button and syntax highlighting — tag the fence with a language for the colours.
  • External links open in a new tab; images are lazy-loaded.
  • Reading time is computed from the actual word count.

Everything is sanitized before it reaches the DOM, so a paste from somewhere else cannot smuggle a script into the page.

Local preview

The site reads posts.json over fetch, which browsers block on file://. Serve the folder instead:

python3 -m http.server 8000
# then open http://localhost:8000/blog/
