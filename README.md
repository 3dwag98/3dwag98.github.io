# 3dwag98.github.io

Personal site for **Chintamani Gawade** — a scrollytelling portfolio plus a Markdown/HTML blog,
served as static files by GitHub Pages. No build step, no framework, no npm install to deploy.

```
.
├── index.html              # the portfolio (scrollytelling)
├── 404.html
├── .nojekyll               # serve files verbatim — Jekyll would eat the raw .md posts
├── feed.xml  sitemap.xml   # generated by tools/build-index.mjs
├── assets/
│   ├── css/  site.css      # design tokens + shared chrome
│   │        home.css       # the portfolio scenes
│   │        blog.css       # log index, article reader, prose
│   ├── js/   core.js       # Lenis + GSAP/ScrollTrigger runtime, cursor, rail, reveals
│   │        home.js        # the scrollytelling scenes
│   │        posts.js       # posts.json contract (shared)
│   │        blog.js        # log index: search + tag filter
│   │        post.js        # article reader: Markdown/HTML -> prose
│   └── vendor/             # GSAP, ScrollTrigger, Lenis, marked, DOMPurify, Prism (pinned copies)
├── blog/
│   ├── index.html          # the archive
│   ├── post.html           # the reader (?p=<slug>)
│   ├── posts.json          # the index of entries
│   └── posts/              # the entries themselves (.md or .html)
└── tools/build-index.mjs   # regenerates posts.json + feed.xml + sitemap.xml
```

## Running it locally

The blog reads `posts.json` and post files over `fetch`, which browsers block on `file://`.
Serve the folder:

```bash
python3 -m http.server 8000
# http://localhost:8000
```

## Writing a post

1. Drop a file in `blog/posts/` — `my-entry.md` or `my-entry.html`.
   The filename (minus extension) becomes the slug and the URL:
   `/blog/post.html?p=my-entry`.

2. Markdown entries carry their own metadata in front matter:

   ```markdown
   ---
   title: Designing for failure
   date: 2026-08-02
   tags: [distributed-systems, resilience]
   summary: One sentence — this is what shows on the index.
   ---

   Body starts here.
   ```

   HTML entries are **fragments** (no `<html>`/`<head>/<body>`) and take their metadata from
   `posts.json`, or from a leading block comment:

   ```html
   <!--meta
   title: Publishing a log
   date: 2026-07-10
   tags: [meta, workflow]
   -->
   ```

3. Register it:

   ```bash
   node tools/build-index.mjs
   ```

   That rescans `blog/posts/`, rewrites `blog/posts.json` (keeping any fields you set by hand),
   recomputes reading times, and regenerates `feed.xml` and `sitemap.xml`. Editing
   `posts.json` by hand works just as well — the script is a convenience, not a dependency.

4. Commit and push. GitHub Pages serves it as-is.

### Manifest fields

| Field | Required | Notes |
| --- | --- | --- |
| `slug` | yes | URL key — `post.html?p=<slug>` |
| `title` | yes | Index entry and page title |
| `date` | yes | `YYYY-MM-DD`; sorts the archive, newest first |
| `summary` | no | One line under the title on the index |
| `tags` | no | Drives the filter chips on `/blog/` |
| `format` | no | `md` (default) or `html` |
| `file` | no | Defaults to `posts/<slug>.<format>` |
| `readingTime` | no | Written by the build script; the reader recomputes it anyway |
| `draft` | no | `true` hides it from the index — reachable via `?drafts=1` |

The reader adds heading anchors, a scroll-spying table of contents, code headers with a copy
button, Prism syntax highlighting, lazy images and prev/next links. Everything is passed
through DOMPurify before it touches the DOM.

## Editing the portfolio

`index.html` is plain semantic HTML — the copy lives there, not in JavaScript. Each scene is a
`<section>` with an `id` and a `data-chapter` label that the left-hand rail reads automatically.

| Scene | Section | What drives it |
| --- | --- | --- |
| 00 Init | `#hero` | char-split intro, parallax, canvas node field |
| 01 Profile | `#profile` | terminal panel, static |
| 02 Creed | `#creed` | **pinned + scrubbed**: "get busy living / or / get busy dying" |
| 03 Stack | `#stack` | **pinned**: the card rail scrolls sideways (desktop; swipeable below 900px) |
| 04 Trajectory | `#trajectory` | sticky company column, hairline draw-in |
| 05 Impact | `#impact` | counters tick up on entry (`data-count`) |
| 06 Base | `#base` | education |
| 07 Logs | `#logs` | latest entries, pulled live from `blog/posts.json` |
| 08 EOF | `#contact` | contact |

Add reveal-on-scroll to any element with `data-anim="rise"`, `"rise-sm"` or `"fade"`
(optionally `data-delay="0.2"`). Colours, spacing and type live as custom properties at the top
of `assets/css/site.css` — change `--accent` there and the whole site follows.

### A note on pinned sections

Pinned sections add height to the page, so any ScrollTrigger created before them measures a
stale layout. The two pins therefore set `refreshPriority` (20 for the creed, 10 for the stack)
so they refresh first and every other trigger measures the final page. If you add another pin,
give it a positive `refreshPriority` too.

## Accessibility and fallbacks

- `prefers-reduced-motion: reduce` disables Lenis, the pins, the boot sequence and the canvas;
  every animated element renders in its final state and counters show their final numbers.
- With JavaScript off, nothing is hidden — the portfolio and the blog chrome degrade to plain
  scrolling documents (post bodies need JS, since they are fetched).
- The custom cursor only appears for fine pointers; touch devices keep the native one.
- Libraries are vendored in `assets/vendor/` at pinned versions, so the site does not depend on
  a CDN staying up: GSAP 3.15, Lenis 1.3, marked 18, DOMPurify 3.4, Prism 1.30.
